# NTIN Catalog Automation

**Автоматизация регистрации товаров в Национальном каталоге товаров Казахстана (NTIN).**

*English: a Python toolkit and Telegram bot that helps small shops in Kazakhstan get NTIN product codes (mandatory on receipts since 2026): it checks barcodes against a local supplier-code database and the national catalog API, prepares and submits registration requests, handles duplicates and moderation, and exports a code table for the cash register.*

## Зачем

С 2026 года малому бизнесу Казахстана нужен код NTIN товара в чеке. Для магазина с тысячами позиций вносить их вручную очень долго, а часть товаров (китайские, без штрихкодов и документов) не имеет готовых карточек. Проект закрывает три задачи:

1. **Найти готовые коды** (в прайсах поставщиков и в каталоге) и не создавать лишнего.
2. **Зарегистрировать недостающие товары** через API каталога: собрать заявку, отправить на модерацию, разобрать дубли, опубликовать.
3. **Дать продавцам простой ответ**: сфотографировал штрихкод, бот ответил кодом или записал товар в список на регистрацию.

## Что умеет

| Модуль | Что делает |
| --- | --- |
| `check_ntin.py` | Пакетная проверка штрихкодов из Excel: контрольная цифра GTIN, поиск в базе и в каталоге, статусы (найден, нет, дубли, деактивирован, внутренний код) |
| `import_supplier.py` | Добавляет прайс поставщика (Excel/CSV) в базу кодов: сам находит колонки, возвращает потерянный Excel-ом ведущий ноль, не создаёт дублей, делает резервную копию |
| `audit_base.py` | Проверяет каждый код базы по каталогу: действует, отключён или неизвестен; итог по источникам. Каталог только читает, базу не меняет |
| `clean_base.py` | По результату проверки убирает отключённые коды, дописывает недостающие штрихкоды из каталога, убранные коды сохраняет отдельно (по их штрихкодам можно искать действующие замены) |
| `oktru.py`, `dicts.py` | Справочники каталога в локальной SQLite: категории ОКТРУ (около 114 тысяч), ТН ВЭД (около 13,5 тысячи), страны, единицы измерения; поиск по словам |
| `card.py` | Сборка заявки на карточку товара и проверка полей до отправки |
| `submit.py` | Отправка заявок: создание, модерация, решение по дублям, публикация, выгрузка кодов. **Без флага `--go` ничего не меняет** |
| `bot.py` | Telegram-бот: читает штрихкод с фото (OpenCV), отвечает кодом, ведёт список «нужно зарегистрировать» |
| `nkt_client.py` | Клиент API: паузы между запросами, повторы при 429/5xx, понятные ошибки, ключ нигде не печатается |

## Как это работает

```
Прайс поставщика ──► import_supplier ──► база кодов (CSV)
                                              │
Фото/цифры штрихкода ──► бот / check_ntin ────┤──► код найден: ответ продавцу
                                              │
                                              └──► не найден: список ──► card ──► submit ──► модерация ──► NTIN
```

## Быстрый старт

```bash
git clone <ссылка на репозиторий> && cd ntin-catalog-automation
python3 -m venv venv && source venv/bin/activate
pip install -r requirements.txt
cp .env.example .env              # впишите свои ключи (файл .env в Git не попадает)
cp examples/base_ntin_example.csv base_ntin.csv   # пример базы кодов

python check_ntin.py товары.xlsx --col "Штрихкод" --out результат.xlsx
python import_supplier.py прайс.xlsx --source "Поставщик" --dry-run
python audit_base.py                 # проверить все коды базы по каталогу (только чтение)
python clean_base.py                 # убрать отключённые коды: base_ntin_clean.csv и base_ntin_inactive.csv
python oktru.py download && python oktru.py search "накладные ногти"
python bot.py
```

Ключ API каталога выдаётся в личном кабинете nationalcatalog.kz. Токен бота — у @BotFather.

## Telegram-бот

- Входит по общему коду: пользователь пишет `/join КОД` (код хранится в `.env`).
- Команды для всех: `/start`, `/help`, `/id`, `/join`, `/find`. Для администраторов: `/stats`, `/notfound`, `/export`, `/users`, `/remove`.
- Поиск готового кода по названию (нужен для товаров, у которых в каталоге нет штрихкода): кнопка «🔎 Найти по названию» или `/find слова`; найденные коды перепроверяются по каталогу, отключённые не показываются.
- Постоянные кнопки под полем ввода (у администратора ещё список ненайденных, статистика, экспорт, люди) и меню команд.
- Принимает фото штрихкода, штрихкод цифрами, несколько штрихкодов в одном сообщении (до 5).
- Запуск на сервере как служба systemd: пример в `deploy/ntin-bot.service.example`.

## Безопасность и надёжность

- Секреты (ключ API, токен бота, код входа) только в `.env`; токен маскируется во всех записях журнала, в том числе в тексте ошибок.
- Защита от подбора кода входа (лимит по пользователю и общий), посторонним бот отвечает редко.
- Выгрузка в CSV экранирует значения, похожие на формулы Excel.
- Защита от «картинок-бомб»: размер снимка проверяется по заголовку до распаковки.
- Бот переживает перезапуск: номер сообщения сохраняется до обработки, остановка по сигналу SIGTERM корректная, сетевые сбои и ограничения Telegram обрабатываются.
- Операции, меняющие данные в каталоге, требуют явного флага `--go`.

python -m unittest discover -s tests -v

38 тестов без сети и токенов (каталог подменяется заглушкой): проверка штрихкодов, разбор сообщений, права доступа, списки по последнему статусу, поиск по названию и кнопки, защита CSV, загрузка прайсов, проверка и очистка базы.

## Статус и ограничения

- Пилот на одном реальном магазине (косметика и аксессуары): зарегистрировано более 10 карточек, для остальных товаров найдены готовые коды. На других типах товаров (продукты, электроника, маркируемые товары) система не проверялась.
- Бот рассчитан на небольшую команду (обработка сообщений по очереди, одна база); для многих магазинов нужна отдельная доработка.
- Для товаров без штрихкода используются общие карточки по видам товара; допустимость такого подхода нужно уточнять у поддержки каталога. Код NTIN не заменяет документы на происхождение и соответствие товара.
- Следующий этап (не сделан): чтение упаковки ИИ для автоматической подготовки карточек с подтверждением владельцем.
